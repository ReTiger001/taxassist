服务与价格

本站在本机运行，把国家税务总局与 31 个省级税务局的公开政策文件收进一个可检索的库。 对外提供两种调用能力：政策检索与税务助手。

两种能力，分开计价

计价口径是按调用次数，不按流量 —— 政策正文体量很小，成本不在带宽上。 两项服务分开计价、分开扣减：

能力做什么成本量级计价
政策检索 全文检索、按条件筛选、取单篇政策原文 本机库查询，毫秒级 按次
税务助手 结合客户业务事实，出带依据的税务分析报告 调用本机 14B 模型，每次数十秒 按次（单价高于检索）

助手单价高于检索是成本决定的：一次助手调用要跑一次大模型（首字约 2 秒、 整篇约 20 秒），而一次检索是对本机索引的查询。具体单价见合同。

余额与扣费规则

  • 余额预充：检索与助手各有一份余额，互相不占用。
  • 成功才扣：请求失败不扣费；余额不足时返回 402，不会让余额变成负数。
  • 充值方式：人工充值 —— 与本方确认金额后由后台入账，即时生效。
  • 用量可查：每一笔调用都有记录（时间、类型、扣减、成功与否），可随时核对。

数据边界（请先读这一条）

本站收录的全部是公开政策文件，来自国家税务总局与各省税务局官网。 你的业务数据不出本机：助手调用时传入的业务事实仅用于当次分析， 不写入任何政策库、不发送给任何第三方 —— 助手本身也是在本机模型上跑的。 所有效力判断都附依据原文与来源网址，可逐条核验。

Service & Pricing

This site runs entirely on the local machine, bringing the public policy documents of the State Taxation Administration and 31 provincial tax bureaus into one searchable knowledge base. Two capabilities are offered for external use: policy search and the tax assistant.

Two capabilities, priced separately

Billing is per call, not by bandwidth — policy text is small, so the cost is not in data transfer. The two services are metered and charged separately:

CapabilityWhat it doesCost scaleBilling
Policy search Full-text search, filtered browsing, fetch a single document Local index query, milliseconds Per call
Tax assistant Analysis with citations, grounded in your stated business facts Runs the local 14B model, tens of seconds per call Per call (higher unit price)

The assistant costs more because each call runs a large language model (roughly 2 s to first token, ~20 s for a full report), whereas a search is an index lookup. Unit prices are stated in the agreement.

Balance and charging rules

  • Prepaid balance: search and assistant have separate balances; neither consumes the other.
  • Charged only on success: failed requests cost nothing; when the balance runs out the API returns 402 and the balance never goes negative.
  • Top-up: manual — confirm the amount with us and it is credited to your account, effective immediately.
  • Usage is auditable: every call is logged (time, type, amount, success), so you can reconcile at any time.

How to connect

Option 1: HTTP API

For your own systems. Authenticate with an issued key; only a hash of the key is stored server-side, and keys can be reissued or revoked immediately.

EndpointDescription
GET /api/overviewKnowledge base overview (coverage, volume)
GET /api/searchFull-text search with region / column / validity / year filters
GET /api/policy/{id}Fetch one policy with its validity grounds
POST /api/mcpMCP protocol entry point (below)

Pass the key with each call:

curl -H "Authorization: Bearer tk_your_key" \
     "http://host:port/api/search?q=R&D super deduction"

Option 2: MCP (for AI clients)

If your workflow lives in an MCP-capable AI client such as Cursor or Claude Desktop, you can attach these capabilities directly and let the model look up policies and fetch source text itself. The methods match standard MCP and share the same key and the same balance.

ToolPurpose
search_policiesSearch policies
get_policyFetch one policy
lookup_by_doc_noLook up by document number
kb_overviewKnowledge base overview

Free trial

New clients can request a trial allowance — a number of calls for each capability, enough to run the full integration end to end. Trial calls are logged like any other, so you can gauge real consumption.

Data boundary (read this first)

Everything in the knowledge base is public policy documents from official tax authority websites. Your business data never leaves this machine: facts you supply to the assistant are used for that single analysis, written to no knowledge base, and sent to no third party — the assistant itself runs on a local model. Every validity judgement carries its source snippet and URL for verification.

Getting started

  1. Contact us with the capabilities you need (search / assistant / both) and your expected volume.
  2. We create a client account, issue a key, and credit a trial allowance.
  3. Call the API as shown above; usage and balance stay auditable throughout.
