接入文档

怎么拿 Key、怎么调、怎么接进 AI 客户端，以及哪些调用不计费。

一、先拿到 Key

在「我的账户」页点「申请一枚新 Key」即可，申请即发、不需要审批。Key 只在签发那一次显示，请立刻保存 —— 库里只存它的哈希，谁也拿不回明文。

丢了就回那一页吊销旧的、再申请一枚。页面上那 12 位“标识”就是用来认出哪一枚是哪一枚的。

← 回我的账户

二、认证方式

每个请求带一个请求头，Key 前面加 Bearer 和一个空格：

Authorization: Bearer tk_你的密钥

Key 与网页登录是两套东西：登录用的是浏览器 Cookie，调 API 用的是这枚 Key。改密码、退出登录都不影响已发的 Key；要停用请显式吊销。

三、四个端点

方法与路径 用途 计费
GET /api/overview 库的概况：收录量、覆盖范围 按次（检索）
GET /api/search 政策全文检索，可筛选排序 按次（检索）
GET /api/policy/<标识> 取单篇政策原文与效力依据 按次（检索）
POST /api/mcp MCP 协议入口，给 AI 客户端用（见第六节） 按次（检索）

GET /api/search 的参数

参数 类型 / 默认 说明
q字符串，空关键词。支持中文、文号片段、英文缩写（如 VAT、CIT）。留空则按筛选条件列出。
tax字符串，空税种筛选（如“增值税”“企业所得税”）
region字符串，空地区筛选（如“全国”“北京”）
effect字符串，空效力筛选（现行有效 / 已废止 / 部分失效 等）
year字符串，空发文年份（如 2024）
column字符串，空栏目筛选（如“通知公告”）
sort字符串，relevance排序：relevance（相关度）或 date（按发文日期）
limit整数，20每页条数
offset整数，0偏移，用于翻页

四、能直接复制运行的示例

把 <主机:端口> 和 <你的密钥> 换成实际值即可。

① 看库的概况

curl -H "Authorization: Bearer tk_你的密钥" \
  "http://<主机:端口>/api/overview"

② 检索（带筛选与排序）

curl -H "Authorization: Bearer tk_你的密钥" \
  "http://<主机:端口>/api/search?q=研发费用加计扣除&region=全国&sort=date&limit=5"

③ 取单篇原文（标识从检索结果里拿）

curl -H "Authorization: Bearer tk_你的密钥" \
  "http://<主机:端口>/api/policy/<检索结果里的标识>"

④ 响应长什么样

检索返回 JSON：hits 是结果数组，total_matched 是命中总数，has_more 表示还能继续翻页，hint 给出下一步建议。每条含标题、文号、发文机关、地区、日期、税种、效力状态、原文链接与摘录。

{
  "hits": [
    {
      "doc_uid": "...",
      "title": "...",
      "doc_no": "...",
      "doc_no_confidence": "...",
      "effect_status": "现行有效",
      "pub_name": "国家税务总局",
      "region": "全国",
      "column": "通知公告",
      "pub_date": "2023-...",
      "tax_types": ["企业所得税"],
      "url": "https://...",
      "snippet": "..."
    }
  ],
  "total_matched": 4286,
  "returned": 2,
  "has_more": true,
  "query_used": "增值税",
  "mode": "fts",
  "hint": "共命中 4286 条，本次返回 2 条。可用 offset=2 继续取，或加筛选条件收窄。",
  "error": null
}

两个字段值得留意：total_matched 是全库命中数（不是本次返回条数，那看 returned）；每条都带 url，可直接打开原文核对。取单篇政策时另会返回正文与效力依据（依据原文 + 来源网址）。

五、错误码与计费规则

状态码 含义 是否扣费
200成功扣
400参数有问题（比如排序值不认识），响应里 error 写明原因不扣
401没有带 Key，或 Key 无效 / 已被吊销不扣
402余额不足。响应体里给出该怎么充值不扣
404要取的那篇政策不存在不扣
503服务或检索暂时异常不扣

只有 200 才扣费。余额在扣减时不会变成负数；余额不足时直接返回 402，请求本身不会被执行。

六、接进 AI 客户端（MCP）

如果你的工作流在 Cursor、Claude Desktop 这类支持 MCP 的客户端里，可以让模型自己查政策、取原文。本服务用的是 MCP over HTTP：请求体放一条 JSON-RPC 消息，响应体放对应的回复，方法与标准 MCP 一致。

可用的四个工具

工具 用途
search_policies检索政策
get_policy取单篇政策原文
lookup_by_doc_no按文号查
kb_overview库概况

握手：先问服务支持什么

curl -X POST -H "Authorization: Bearer tk_你的密钥" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize",
       "params":{"protocolVersion":"2025-06-18"}}' \
  "http://<主机:端口>/api/mcp"

列出工具 / 调用工具

{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}

{"jsonrpc":"2.0","id":3,"method":"tools/call",
 "params":{"name":"search_policies",
           "arguments":{"query":"增值税","limit":3}}}

在客户端里配置时，把地址填成 http://<主机:端口>/api/mcp、鉴权头填上你的 Key 即可；MCP 调用与网页共用同一份检索余额，也共用同一枚 Key。

七、常见问题

Key 泄露了怎么办？
回「我的账户」点那一枚的「吊销」，它立刻失效（用它调用的程序会收到 401），然后申请一枚新的。吊销不可撤销。

余额用完了会怎样？
接口返回 402，请求不会执行、也不扣费。充值后立刻恢复 —— 检索与助手是两份余额，一份用完不影响另一份。

怎么充值？
走人工充值：与对接人确认金额和方式，转账时备注你的账户名，管理员确认后即时入账。回「我的账户」页刷新就能看到新余额。

怎么知道自己用了多少？
「我的账户」页有余额和最近 40 次调用明细（时间、类型、结果、扣减）。每一笔都记账，可以逐条核对。

业务数据会被存下来吗？
不会。政策库只收公开政策文件；你传给助手的业务事实仅用于当次分析，不写入任何库、不发给任何第三方 —— 助手本身也是在本机模型上跑的。
