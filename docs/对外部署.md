# 对外提供访问：部署、发号、运维

这份文档讲的是"让外部使用者（外勤同事、客户）打开网址就能用"这件事，
以及**你会因此承担什么、出了事怎么收场**。

---

## 0. 先决定：这一步值不值得

本站默认只监听 `127.0.0.1`，也就是只有这台电脑能打开。一旦对外：

- 被攻破的不只是这个网站，而是**这台工作机上的全部数据**（客户底稿、其他文件）。
- 这台机器从此刻起变成"对外服务"，需要持续维护：看日志、更新依赖、及时撤销访问。
- **对外暴露的合规性要由你向 EY IT / 风险部门确认** —— 这不在技术能决定的范围内。

如果只是自己用：什么都不要做，直接 `python -m taxassist serve` 即可。

---

## 1. 站点自带的门锁（你拥有什么）

| 机制 | 实际行为 |
| --- | --- |
| 未登录 | 一律跳转到登录页，**看不到任何内容** |
| 注册 | **必须有邀请码**，没有开放注册；一个码只能注册一个账号 |
| 口令 | 至少 10 位；只存 scrypt 哈希，不存原文（等于本站也不掌握你的口令） |
| 会话 | 签名 Cookie，12 小时；`HttpOnly` + `SameSite=Lax` |
| 改口令 / 删号 | **已登录的浏览器立刻掉线**，不需要额外操作 |
| 爆破防护 | 同一账号 5 分钟内失败 8 次即暂时锁定；注册按来源限速 |

**唯一的硬前提：必须走 HTTPS。** 登录是把口令 POST 给服务端的，
在 HTTP 上这是明文 —— 等于把口令交给网络路径上的每一个节点。
下面两条路径都自带 HTTPS，不需要你自己申请证书。

---

## 2. 三条路径，先选一条

| | 使用者要做什么 | 页面内容经过谁 | 公网暴露 | 建议 |
| --- | --- | --- | --- | --- |
| **A. Tailscale** | 装客户端、加入你的网络 | 只在你的设备之间（端到端加密） | 不开任何端口 | **首选** |
| **B. Cloudflare Tunnel** | 什么都不用，打开网址 | Cloudflare 边缘节点（**能看到明文**） | 不需要公网 IP | 使用者较多、不想让对方装东西时 |
| **C. 路由器端口转发** | 打开网址 | 只有你的机器 | 端口直接开给全网 | **不建议** |

关于"数据不出本机"：**A 最接近这个承诺**——流量在你自己的设备之间点对点加密，
第三方看不到内容（但要每个使用者装一次客户端）。
**B 会把页面内容解密在 Cloudflare 的边缘节点上**：库里的政策正文是总局公开信息，
但**内部推定结论、待确认清单、附件解析全文**是本系统的内部产物。
若这一点对你构成问题，选 A。

---

## 3. 路径 A：Tailscale（推荐）

1. 你和每个使用者各自在 tailscale.com 注册账号（个人版免费，人数少够用）。
2. 在**这台机器**上安装 Tailscale 客户端并登录，记下它的机器名。
3. 在本机生成 tailnet 内的 HTTPS 证书并转发（Tailscale 会自动签发，不用买域名）：

   ```bash
   taxassist serve --expose
   # 另开一个窗口：
   tailscale serve --bg https / http://127.0.0.1:8765
   ```

4. 把 `https://<你的机器名>.<你的tailnet>.ts.net` 发给使用者。
   他们必须已经加入你的 tailnet，否则打不开 —— **这本身就是一道门锁**。

> `--expose` 不能省。它的意思是"只监听本机，但按对外提供服务对待"。
> 隧道/反向代理的标准做法都是让后端只监听本机；若不加 `--expose`，
> 认证不会被启用，**等于门锁被自己拆掉**。

---

## 4. 路径 B：Cloudflare Tunnel

1. 需要一个域名，并把它的 DNS 托管在 Cloudflare（免费套餐即可）。
2. 在**这台机器**上安装 `cloudflared`，然后：

   ```bash
   cloudflared tunnel login
   cloudflared tunnel create taxassist
   cloudflared tunnel route dns taxassist tax.你的域名
   ```

3. 写 `config.yml`，把流量指到本机后端：

   ```yaml
   tunnel: taxassist
   credentials-file: C:\Users\<你>\.cloudflared\<tunnel-id>.json
   ingress:
     - hostname: tax.你的域名
       service: http://127.0.0.1:8765
     - service: http_status:404
   ```

4. 起服务与隧道（两个窗口）：

   ```bash
   taxassist serve --expose
   cloudflared tunnel run taxassist
   ```

5. 建议再加一层 Cloudflare Access（Zero Trust → Access → 应用），
   要求邮箱验证码才能进入 —— 多一道门，代价是使用者多一步。

---

## 4.5 路径 C：Cloudflare 临时隧道（不用注册，地址会变）

**这是目前最省事的一条**，代价是地址不固定，且页面内容经过 Cloudflare。

```bash
# 起服务（只监听本机，由隧道转发进来 —— --expose 不能省）
python -m taxassist serve --expose

# 另开一个窗口：一条命令拿到公网 HTTPS 地址
tools\cloudflared.exe tunnel --url http://127.0.0.1:8765 --no-autoupdate
```

输出的 `https://****.trycloudflare.com` 就是对外地址。已实测验证：
未登录会被拦到登录页、邀请码注册可用、会话 Cookie 在 HTTPS 下自动带 `Secure`。

**注意三件事**：

1. **地址每次重启都会变**（随机分配）。要固定地址就得用自己的域名走路径 B。
2. **没有可用性保证**（Cloudflare 的免费临时隧道本就用于试验）；
   要长期对外用，应当走路径 B 或用 Tailscale。
3. **本机若开着代理，你自己反而打不开**。这台机器的系统代理是
   `127.0.0.1:7897`；请把 `*.trycloudflare.com` 与 `*.cloudflare.com`
   加进代理规则的直连列表，否则浏览器会直接 `ERR_CONNECTION_CLOSED`
   （`curl` 不受影响，因为它默认不读系统代理 —— 遇到"curl 通、浏览器不通"
   就是这个原因）。

### 下载 cloudflared（国内网络下 github.com 可能不通）

`github.com` 打不开时，用 GitHub API 绕过（`api.github.com` 与
`objects.githubusercontent.com` 通常可达）：

```bash
# 1. 取最新版本里 Windows 版资源的 API 地址
curl -s "https://api.github.com/repos/cloudflare/cloudflared/releases/latest" -o cfrel.json
grep -oE '"url": *"[^"]*assets/[0-9]+"|"name": *"[^"]*"' cfrel.json | grep -B1 "windows-amd64.exe"

# 2. 用上一步得到的 assets 编号下载（必须带 Accept: application/octet-stream）
curl -sL -H "Accept: application/octet-stream" -o tools/cloudflared.exe \
  "https://api.github.com/repos/cloudflare/cloudflared/releases/assets/<编号>"

# 3. 验证
tools/cloudflared.exe --version
```

仓库里已有 `启动对外访问.bat`，双击即可完成上面全部步骤。

## 5. 发号与撤销

**发一个邀请码（一码一人）**

```bash
python -m taxassist invite --note "客户张三" --days 30
```

输出形如 `邀请码：QRQR-CXY6-QFFN`。把**网址、邀请码、`/register` 这个页面**一起发给对方，
口令由对方自己设定（你不需要也不应该替他设）。

**看现在都发了哪些**

```bash
python -m taxassist invite --list
```

**码发错了 / 发多了 —— 吊销未使用的码**

```bash
python -m taxassist invite --revoke QRQR-CXY6-QFFN
```

**撤销已经开通的人**（合作结束、笔记本丢失、口令外泄）

```bash
python -m taxassist userdel 账号名
```

对方浏览器里那个登录状态**立刻失效**，不需要额外操作。

**给某人重置口令**

```bash
python -m taxassist useradd 账号名
```

同名即重置口令，旧会话同样立即失效。**这一条也是口令疑似泄露时的应急手段。**

## 6. 日常运维（每周花两分钟）

1. 抓取是否正常：

   ```bash
   python -m taxassist status
   ```

2. 有没有人在试口令：看服务窗口里的日志，出现下面这行说明有人在猜：

   ```
   登录失败：someone（近 300 秒内第 3 次）
   ```

   偶尔几次是使用者自己输错；**持续出现同一账号或大量不同账号就要处理**：
   吊销相关邀请码、重置口令，必要时先停掉隧道。

3. 依赖更新（公网暴露后这是持续责任）：

   ```bash
   .venv/Scripts/python.exe -m pip list --outdated
   ```

## 7. 不要做的事

- **不要在 HTTP 上对外**（口令明文）。
- **不要把 8765 端口在路由器上直接转发给公网** —— 那是没有 HTTPS 托管、
  IP 会变、被扫描到就是裸奔的最差组合。
- **不要开放注册**。本站刻意没有开放注册：能注册就等于没有门锁。
- **不要把同一个邀请码发给多人**，也别贴在群里 —— 一码一人，贴群里等于谁都能先用掉，
  而且事后查不出是谁在用。
- **不要在共享电脑上勾"记住密码"**；用完点右上角"退出"。
- 不要把库文件、`data/` 目录复制给外部使用者 —— 对外只给网页访问。

---

## 8. 出事时的处置

| 情况 | 动作 |
| --- | --- |
| 怀疑某人口令泄露 | `useradd <账号>` 重置口令（立即踢掉旧会话） |
| 某人不再需要访问 | `userdel <账号>` |
| 邀请码外流 | `invite --revoke <码>`（已使用的码吊销无效，直接删对应账号） |
| 怀疑机器被入侵 | 先 Ctrl+C 停服务、停掉隧道，再按公司流程处理 |
| 想临时全部切断 | 停掉隧道即可（后端只监听本机，外部立刻不可达） |

## 9. 排错

| 现象 | 原因 |
| --- | --- |
| 浏览器弹出原生"需要登录"框，不是登录页 | 用的是 `--auth basic`；改用默认的 `--auth page` |
| 打开就是内容，没有登录页 | **认证没启用**。检查启动命令里有没有 `--expose`（或 `--host 0.0.0.0`） |
| 登录成功后立刻又跳回登录页 | 隧道没有转发 `X-Forwarded-Proto`（Cloudflare 与 Tailscale 都会带；自建 nginx 要手动加 `proxy_set_header X-Forwarded-Proto $scheme;`） |
| 隧道通了但连不上后端 | 后端服务没起，或 `service:` 写的端口不是 8765 |
| 登录页提示"本站尚无账号" | 还没有任何人注册过；先 `python -m taxassist invite` 生成邀请码 |

**验证门锁是否真的开着（每次改完部署都做一次）**：
用另一台设备、或浏览器的隐身窗口打开网址 —— 应当**只**看到登录页。

---

## 10. 最小操作清单

```bash
# ① 起服务（本机监听 + 按对外对待）
python -m taxassist serve --expose

# ② 另一个窗口：把流量转进来（二选一）
tailscale serve --bg https / http://127.0.0.1:8765
cloudflared tunnel run taxassist

# ③ 发一个邀请码
python -m taxassist invite --note "发给谁" --days 30

# ④ 把「网址 + 邀请码」发给对方，让他打开 /register 自己注册

# ⑤ 用隐身窗口确认：只看到登录页
```

站点**第一次**对外时没有任何账号，登录页会提示"本站尚无账号" ——
这是正常的，按 ③ 发码即可。反过来，只有邀请码而没有账号时，**谁也进不来**。
